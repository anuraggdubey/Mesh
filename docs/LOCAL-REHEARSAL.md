# Local rehearsal (free, no faucet)

Runs the whole stack on one machine against a throwaway local chain: API, contracts, two real provider workers running
the real render image in Docker. Use it to test changes without spending testnet HBAR. It uses the public anvil test keys
(worthless anywhere real). Verified 2026-11-06: tiny and small render jobs end to end on Windows.

## What you need

- Docker Desktop running (provider workers run the job image in Docker).
- Foundry installed (`anvil`, `forge`); on Windows the default location is `C:\Users\<you>\.foundry\bin` (or set `FOUNDRY_BIN`).
- `npm install` done.

## 1. A local registry and the render image

Workers pull job images **by digest** from a registry, so a locally built image must be pushed to one:

```bash
docker run -d -p 5000:5000 --name mesh-registry registry:2
docker build --platform linux/amd64 -t localhost:5000/mesh-render:dev jobs/render
docker push localhost:5000/mesh-render:dev          # prints: dev: digest: sha256:<digest>
```

Put the image into `.env.localchain.image` (git-ignored, any file named `.env.*` is):

```
RENDER_IMAGE_REF=localhost:5000/mesh-render
RENDER_IMAGE_DIGEST=sha256:<digest from the push>
```

Optional resource limits for the workers in `.env.localchain.limits`: `PROVIDER_CPUS=2` and `PROVIDER_MEMORY=1g`.

## 2. Start everything (one terminal each)

```bash
npm run chain:local                                  # anvil + contracts + two registered, staked providers; writes .env.localchain*
npm run with-env -- .env.localchain .env.localchain.image -- npx next dev -p 3200      # the API
npm run with-env -- .env.localchain .env.localchain.limits .env.localchain.providerA -- npm run worker:provider
npm run with-env -- .env.localchain .env.localchain.limits .env.localchain.providerB -- npm run worker:provider
```

`scripts/with-env.ts` loads env files over the current environment, so no shell tricks are needed on Windows.

## 3. Run a job

Open http://localhost:3200, pick a size and enter any wallet address, or use curl:

```bash
curl -X POST http://localhost:3200/api/jobs -H 'content-type: application/json' \
  -d '{"type":"render","preset":"tiny","requester":"0x6834228cb6F180C05fA2154a2B2670d92c4FDf59"}'
```

The local config turns on `MESH_DEV_SKIP_PAYMENT`, `MESH_DEV_SKIP_WORLD` and `MESH_DEV_AUTO_APPROVE` (all DEV ONLY) and `MESH_CHAIN_LOOP`, which starts the chain loop inside the API process (see below).

## The chain loop (step 11)

With `MESH_CHAIN_LOOP=true` the API starts a background loop (every 3 s) that, for each job:

1. **locks** the payment in escrow (in dev mode the API first mints test tokens to the escrow, because no real x402 payment exists),
2. **posts the claim** on chain once every provider has signed (opens the challenge window),
3. **finalizes** after the window, and the contract pays the providers from escrow.

Finalizing needs an approval: a verifier verdict of `ok` (verifier worker, next step) or the dev-only `MESH_DEV_AUTO_APPROVE`.
A job whose chain step fails 4 times is ended and its payment refunded. Providers must be registered and staked on chain to be
assigned a job. `GET /api/receipts/:jobId` returns the receipt as the contract holds it. After changing the loop's code, restart the API.
The loop picks up where it left off: a job left `pending` finalizes after a restart.

## What was checked

- Both real workers register, pass the on-chain stake check, pull the image by digest and run it with `--network none`, `--read-only` and CPU/memory limits.
- The `tiny` job's four tile hashes equal `docs/golden/render-tiny.json` (generated on macOS arm64), so Windows Docker output matches macOS byte for byte.
- `small` (2048x2048, 64 tiles) finished in about 41 s with two workers at 2 CPUs each; all tiles uploaded and both claims accepted.

- With the chain loop on, a `tiny` job went created -> final in about 39 s; escrow ended at 0 and the two providers were paid 50000 each, read straight from the token contract. A job left pending finalized after an API restart.

## Notes

- On a real (non-local) chain the loop uses the later of chain time and host time to decide the window is over; a too-early guess is rejected by the contract and simply retried.
- Hedera testnet check: `npm run testnet:smoke` mints test tokens to the escrow, locks and refunds a throwaway job using only the API wallet's gas (about 0.32 HBAR).
- `chainRegistered` on `GET /api/providers` is true for providers registered on `MeshStake`.
- `.env.localchain*` files contain only anvil test keys and are regenerated by `npm run chain:local`. Delete them when done.
